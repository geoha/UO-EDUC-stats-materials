Preparing and Analyzing Survey Data in R

Part 2 Preparing the Data

In this section, we are using R to prepare data for analysis. We will use mock data from the TIMSS Teacher Questionnaire.

2.1 Import the data from the CSV file

I generated these mock data as fake responses to the TIMSS math teacher questionnaire https://nces.ed.gov/timss/pdf/2015_8th_grade_Teacher_Questionnaire_Math.pdf. You can also get real data from their site. We could use the code below with those data (though we would need to address missing values). In other words, this can be part of our data analysis plan and we created data using our best guess about how people would respond. Then, we assume it functions well, and then analyze the real data.

If you’ve opened this RStudio file from the same folder that contains the CSV file, Week13_Timss_Mock_Raw.csv, your working directory will be that location and you can import data using this code:

timss <- read.csv('Week13_Timss_Mock_Raw.csv')

If you prefer to download the data, it will be temporarily available here:

timss <- read.csv("http://www2.hawaii.edu/~georgeha/Handouts/Week13_Timss_Mock_Raw.csv")

2.3 Recoding response-category data

2.3.1 Reverse-coding and rescaling data

Questions 15a–15g have numeric codes that are not logical. For instance, Every or almost every lesson is \(1\) but Never is coded as \(4\). Usually, we use higher values for more of a construct and lower values for less.

So, let’s change our coding so that Never is coded as \(0\), Some lessons is \(1\), About half the lessons is \(2\), and Every or almost every lesson is \(3\). So, we are going from a 4-to-1 scale to a 0-to-3 scale.

The general formula for reverse coding is this:

  • newvalue = (num of response options) + (bottom value of new scale) - (observed value in the original scale)

So with our data in Questions 15a–15g,

  • How many response categories are there? Answer: 4
  • What’s the bottom value on our NEW scale going to be? Answer: 0
  • What are our original data? Answer: all of the data in Q15a through Q15g

2.5 A general formula for rescaling data

Here’s a more general formula for rescaling:

Sometimes, we want to rescale data. For example, if we want to create an index based on several variables, but some of these variables are on a 1-to-5 scale while others are on a 1-to-6 scale and we want to give equal weight to the variables, we would rescale one type to be on the other’s scale.

We can use this general formula, with the “bottom” and the “top” referring to the bottom and top of the scale and the “value” referring to the response of interest (a person’s response): new.value = new.bottom + (old.value - old.bottom)*(new.top - new.bottom)/(old.top - old.bottom) but first we have to assign values to each of the objects on the right side (or we could just plug them in). Here is an example of rescaling a response of 3 that was on a scale of 1 to 6 to the new scale of 1 to 5:

old.value <-  3  #This is our original data point. 
old.bottom<-  1  #This is the lowest possible point on the original scale
old.top   <-  6  #This is the highest possible point on the original scale
new.bottom<-  1  #This is the lowest possible point on the new scale
new.top   <-  5  #This is the highest possible point on the new scale
new.bottom + (old.value - old.bottom)*(new.top - new.bottom)/(old.top - old.bottom)
## [1] 2.6

which is the same as this if we weren’t using object names:

1 + (3 - 1)*(5-1)/(6-1)
## [1] 2.6

Seems like too much work, right. However, we can use this in a custom function.

2.6 Create and use a custom function

It’s convenient to create a custom function using that formula. Let’s name our custom function something that does not already exist in base R. We can check this using the help() function to see if something comes up:

help("myrescale")

Seems like “myrescale” is a good name because nothing comes up in help. After the function(), we specify the argument names and their order. Then, we enclose the operations in the curly brackets. The final object, new.value, is what is produced.

myrescale <- function(old.value, old.bottom, old.top, new.bottom, new.top){
 new.value <- new.bottom + (old.value - old.bottom)*(new.top - new.bottom)/(old.top - old.bottom)
}

Now we can use that custom function. Let’s make up some arbitrary original data, within our original 1 to 6 scale:

olddat <- c(4, 3, 2, 1, 6, 5)

new1to5 <- myrescale(old.value  = olddat, 
                     old.bottom = 1, 
                     old.top    = 6, 
                     new.bottom = 1, 
                     new.top    = 5)
new1to5
## [1] 3.4 2.6 1.8 1.0 5.0 4.2

So, we used our homemade function, myrescale(), by specifying the arguments. We can re-use this function in our R session.

2.8 A shortcut, when all of the items are on the same scale

So far, we have been practicing rescaling items before we use them to create a composite score. That was worth learning because sometimes we find ourselves needing to recode only some of the items (e.g., if we need to reverse-code items that are phrased in the opposite direction to the other items in the scale).

When we do not have that situation, we can take a simpler approach: We can create the composite variable and then rescale that. Here’s an example with Q15.

Q15 <- paste0("Q15_StCentrd_", letters[1:7])
timss$Q15_Index_raw  <- apply(timss[ ,Q15],1, mean, na.rm = TRUE) 
timss$Q15_Index_easy <- 4 + 0 - timss$Q15_Index_raw

Annoying, huh. We did all of the work above when we could have achieved the same result with three lines of code.
