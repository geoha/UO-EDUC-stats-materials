\hypertarget{what-is-r}{%
\chapter{What is R}\label{what-is-r}}

R \citep{R-base} is an open-source language and environment that is primarily used for conducting statistical analyses and managing data. RStudio \citep{RStudio} is an open-source graphical environment for running R, viewing output, and doing other things (like creating this document).

The R community is huge and people develop R packages that we can download (through R) and use for specific types of analyses. In later tutorials, we will use many packages, such as the ggplot2 package \citep{R-ggplot2} and the psych package \citep{R-psych}.

\hypertarget{create-an-r-script-file-in-your-folder-then-start-rstudio-by-double-clicking-that-file}{%
\section{Create an R script file in your folder, then start RStudio by double-clicking that file}\label{create-an-r-script-file-in-your-folder-then-start-rstudio-by-double-clicking-that-file}}

We typically write code in a script file, run it to be sure our coding is correct, then save the file to a location on our local machine so we can continue working on it another day. For a six-minute introductory video on this process, go to \url{https://youtu.be/C8sP6rfrMAs}.

There are at least two ways to create a new R script file:

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  Open RStudio to get a blank source script page; then, save the file (using the \texttt{File} menu), giving it a name with the extension \texttt{.R} and selecting a directory on your computer where you want it to be saved (such as a folder for this class). After doing this, close RStudio. Then, navigate to the folder in which you saved your R script file and open it again by double-clicking on the file. You might need to right click on the file and use \textbf{\texttt{Open\ With}} to direct your computer to open the R file with RStudio.
\end{enumerate}

From there, you should be able to also set your computer to always use RStudio for files with \texttt{.R} extensions. By closing RStudio, and then navigating to your folder to open the R file directly, our R session will automatically set the working directory to be that folder location. In other words, this is the lazy way (which I fully appreciate) because we can avoid having to manually set the working directory.

\hypertarget{if-you-need-to-set-the-working-directory}{%

Note that when you start an RStudio session from a folder location that does \textbf{not} include your data, such as if you access a shortcut on your desktop, you will need create a working directory by entering something like this in your script: \texttt{setwd("C:/Users/Yourname/Desktop/Yourfolder")}.\footnote{The directory path depends on your operating system, how your folders are set up, and of course, where you want to save your file. If you want to see where your working directory is, use the \texttt{getwd()} function.}

An alternative to using the \texttt{setwd()} function is to use RStudio's GUI. So, if you have your data and your R script in a folder, but you're unable to read the data (perhaps because you opened RStudio from your applications menu instead of clicking on the file in your folder), you can do this: Go to the pane that shows your files, plots, packages, and so forth. Open the files tab and navigate to the folder where your data reside by clicking on the ellipsis button \texttt{...} on the right. After that, go to the \texttt{More} menu and select \texttt{Set\ As\ Working\ Directory}.

\hypertarget{saving}{%
\chapter{Saving and closing an R session}\label{saving}}

Notice that after you type any script in your source pane, the file name in the tab will be red and have an asterisk at the end. This means your edits are unsaved. You can save your script at any time (use \texttt{Save} in the \texttt{File} menu or the save shortcut, \texttt{Ctrl+S} or \texttt{Cmd+S} depending on your OS).

After you've saved your work, close RStudio. You'll be prompted whether you'd like to also save the workspace image. If you're like me, you'll say ``Wait a minute. I thought I just saved it. What's this?'' Basically, we have the choice of \textbf{\emph{also}} saving the output we have generated so far. My advice is to \textbf{\emph{not}} save the workspace image unless (a) you're working on something that takes a lot of processing time (e.g., with very large data sets or complex analyses) or (b) you have neared the completion of your project and are making minor tweaks.

\begin{figure}
\centering
\includegraphics{images/DontSaveImage.png}
\caption{Don't save the R image on exit}
\end{figure}

The reason we don't want to save the image is that it is best to start each session anew, without any R objects (assuming you also keep your data file in that same directory).\footnote{R objects are described next.} Then you can run your code and be sure that the mistakes you made in the last session with this file are not included in your current session. If you want to be sure your session is clear, you can go to the \texttt{Environment} pane of RStudio and click on the broom icon to sweep your environment clean.\footnote{You can also clear the console using the broom in that console.}

Let's read the data set into R and save it to an object, which we'll arbitrarily call \emph{dat}. The \texttt{read.csv()} function does just that---it reads CSV files.\footnote{CSV files are comma-separated-value files, which we might have saved from a worksheet in a spreadsheet program such as Excel.} The CSV file needs to be in the same folder as your .R file (or you have set the working directory to that folder, or you have used the directory to the file within quotes). Also, be sure to use quotes around the name. Finally, R is \textbf{case sensitive}, so if you get an error, check the spelling. Type the following code in your source pane in RStudio, place your cursor anywhere on the line, and click the \texttt{Run} button.

A word of caution in working with Likert-type data such as these is worth our attention. We should probably not estimate the mean, variance, and standard deviation with individual Likert-type variables that have fewer than five categories because these types of functions assume the variables are continuous---that is, we are assuming that the conceptual distance between any two neighboring points on the numbered scale is the same as the distance between any other two consecutively numbered points.\footnote{Mean and variance are more appropriate with continuous, interval-level, variables than with ordinal level variables. If our five Likert-type questions are asking about the same concept, we can combine them into a single composite score and save that as a new variable, which we'll call \texttt{Energy} in our data frame. Then we can perform functions, such as \texttt{summary()} and \texttt{var()} on that variable. It's worth noting that after we have this composite score based on multiple Likert-type items, we have a stronger case for assuming that our variable is continuous enough for performing operations like \texttt{mean()}, \texttt{var()}, and so forth; however, some statisticians will still frown against this practice because the summation procedure still assumes equal intervals in the Likert-type item data. In practice, however, with composite variables, this usually does not result in meaningful misinterpretations \citep{carifio_resolving_2008, norman_likert_2010}.

Each person now has a score on our new variable, called \texttt{Energy}, which is the mean across the five Likert-type items. It looks like the average energy level was 2.86 on the \texttt{1} to \texttt{5} scale.

How did we accomplish this? Let's break the code down so it makes sense:

Earlier we created the object \texttt{Likerts} using the \texttt{c()} function and the names of our variables of interest---the five Likert-type questions. In other words, we did this:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{Likerts<-}\StringTok{ }\KeywordTok{c}\NormalTok{(}\StringTok{"Lik1"}\NormalTok{, }\StringTok{"Lik2"}\NormalTok{, }\StringTok{"Lik3"}\NormalTok{, }\StringTok{"Lik4"}\NormalTok{,}\StringTok{"Lik5"}\NormalTok{)}
\end{Highlighting}
\end{Shaded}

Then, we subsetted our data, using indexing, with the column index consisting of our object, \texttt{Likerts}, which comprises the names of the five variables:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{dat[ ,Likerts]}
\end{Highlighting}
\end{Shaded}

We could have achieved the same result with the \texttt{c()} function directly embedded in the index, as in \texttt{dat{[}\ ,c("Lik1",\ "Lik2",\ "Lik3",\ "Lik4","Lik5"){]}} but it would have made our line of code longer and harder to read. Also, we can re-use the \texttt{Likerts} object when we perform other functions (such as \texttt{head(dat{[}\ ,Likerts{]})}).

What is new here is the \texttt{apply()} function. This function has three \textbf{arguments}. The first one specifies the data (rows and columns) we want to apply a function to, the second argument specifies the margin we seek to apply the function to, and the third argument specifies the function we wish to have applied (\texttt{mean} in our case).

\begin{longtable}[]{@{}rl@{}}
\toprule
\endhead
\begin{minipage}[t]{0.07\columnwidth}\raggedleft
\strut
\end{minipage} & \begin{minipage}[t]{0.76\columnwidth}\raggedright
\includegraphics{images/note.png}{ An argument is a statement within a function. Simple functions, like \texttt{summary()} and \texttt{median()} take a single argument. The order of arguments in a function is important so R can distinguish them; otherwise, we need to explicitly identify the argument. The function above, with its three arguments made explicit is \texttt{dat\$Energy\textless{}-\ apply(X\ =\ dat{[}\ ,\ Likerts{]},\ MARGIN\ =\ 1,\ FUN\ =\ mean)}. The argument identifiers are \texttt{X}, \texttt{MARGIN}, and \texttt{FUN}. In our example, I made ``\texttt{MARGIN\ =}'' explicit to bring our attention to it but we can omit the words ``\texttt{MARGIN\ =}'' and simply use the value (\texttt{1} in our case) because it is the second argument in the function.}\strut
\end{minipage}\tabularnewline
\bottomrule
\end{longtable}

In our example, our data are \texttt{dat{[}\ ,Likerts{]}}, as specified by our first argument.\\
The second argument tells R to apply the function to the first margin (\texttt{MARGIN\ =\ 1}), which refers to the rows. (The second margin would apply the mean to the columns, which is not what we seek to do here.) Just as in indexing, the first margin refers to rows and the second margin to columns. In other words, we wish to apply the mean function \emph{along each row} (the first margin) and across the columns to get a mean score for each row.\footnote{We are \emph{applying} the \texttt{mean()} function across Person 1's responses to the Likert-type questions, then applying \texttt{mean()} across Person 2's responses, and so forth until the last person. If we wanted to know the mean response on each column, such as for each variable across all the people, we'd specify \texttt{MARGIN\ =\ 2}.} The result is a vector of values.\\
Look again at our code and notice that the arguments are separated by commas:

\begin{Shaded}
\begin{Highlighting}[]
\NormalTok{dat}\OperatorTok{$}\NormalTok{Energy<-}\StringTok{ }\KeywordTok{apply}\NormalTok{(dat[ ,Likerts], }\DecValTok{1}\NormalTok{, mean)}
\end{Highlighting}
\end{Shaded}

\hypertarget{appending-variables-to-our-data-frame}{%
\section{Appending variables to our data frame}\label{appending-variables-to-our-data-frame}}

Finally, because the result is the same length as the number of rows in our data frame, we can append it as a new column using the \texttt{\$} symbol and a new name, ``\texttt{Energy}'', that we create on the fly: \texttt{dat\$Energy}.\footnote{We can name our new variable anything we like, as long as it begins with a character. Numbers, periods, and underscores, \texttt{\_}, are also acceptable in variable names, but spaces and special characters should be avoided, as should words that are used for functions, such as \texttt{c} or \texttt{mean}. Remember that R is case sensitive!}

Let's again examine our new data frame to see the new variable we created. Notice that it is the last column. Also, let's make sure the calculation was correct: For Person 1, the mean across the responses was \(\frac{5+5+4+3+2}{5}=3.8\), which is the same value reported under the Energy column.

\hypertarget{plotting}{%
\chapter{Creating a simple box plot}\label{plotting}}

R provides many options for creating plots.\footnote{This example uses the base R graphics. We can get fancier plots using the ggplot2 package.} Let's start simple and create a box plot. Because our \texttt{Teacher} variable is a factor, we can use a box plot to see whether the range of responses on our composite variable, \texttt{Energy}, depends on whether or not the school professional is a teacher.\footnote{The tilde, \texttt{\textasciitilde{}}, is used in R to indicate a formula. We will see this in regression and other statistical equations, where it serves the same role as the ``\texttt{=}'' operator (e.g., Y \textasciitilde{} b\textsubscript{0} + b\textsubscript{1}X). Here, we're asking R to make a box plot with a response (or outcome) variable, \texttt{dat\$Energy}, based on the independent (or explanatory) variable,\texttt{dat\$Teacher}. To match the scale of the Likert-type items, we set the scale of the Y axis to go from 1 to 5 using the \texttt{ylim=} argument. We have also specified the X and Y axis labels with the \texttt{xlab=} and \texttt{ylab=} arguments. The line \texttt{par(bty="l")} is for aesthetics. \texttt{bty} stands for box type and the \texttt{l} is a lowercase \texttt{L} to tell R to print only the left and bottom lines of the box (like the shape of the letter \texttt{L}).}

\hypertarget{why-wont-my-code-run}{%
\section{Why won't my code run?}\label{why-wont-my-code-run}}

One of the most frequent problems new users of R experience is when they have run only part of a section of code (such as only the \texttt{2\ +} in the example below) and the console is waiting for them to complete the code. R expects another number. But, when you run another line of code that you are so sure is correct, such as \texttt{dat\textless{}-\ read.csv("SchoolSurvey.csv")}, you keep getting errors. Annoying!

\begin{figure}
\centering
\includegraphics{images/IncompleteCode.png}
\caption{R is waiting for your to enter the next number}
\end{figure}

You can tell if this is the problem if the console has a \texttt{+} at the start of the line. It is expecting something to be added to complete the code. In the example here, R could not understand \texttt{2\ +\ dat\textless{}-\ read.csv("SchoolSurvey.csv"}, so it returned an error.

\begin{figure}
\centering
\includegraphics{images/IncompleteCodeAfter.png}
\caption{Why doesn't my code work?}
\end{figure}

The solution is to place your cursor in the console and then press \texttt{ESC} on your keyboard. Now try your code.

Another strategy is to clear your environment (as described in \protect\hyperlink{saving}{Part 4}) and re-run your code. If we have objects in our R session that have mistakes, they will remain there until we replace them with the correct objects. Clearing the environment ensures they're gone. If you want even more peace of mind, clear your environment, save your R image, and reopen it to run your shiny new code. One troubleshooting strategy, after having cleared your environment, is to run portions of your code to isolate the error.

\begin{figure}
\centering
\includegraphics{images/ClearEnvironment.png}
\caption{Clearing the environment removes previously made objects}
\end{figure}

Finally, if we have error messages in our console, we can copy portions of that message and paste them within quotes into an online search, such as in \url{https://rseek.org/}. This sometimes reveals a solution to our specific problem.

\hypertarget{have-patience-and-keep-learning}{%
\section{Have patience and keep learning}\label{have-patience-and-keep-learning}}

There will be times in our learning of R that we experience frustration. Because it is open source, it is a bit of a wild west environment. Package developers differ in their coding and what they expect us to know about their coding. So, what works with one function in one package might not work with another. We also might discover new workflows as we familiarize ourselves with R. The code in this tutorial is all from R's base R code. In other words, we did not rely on any packages. Another approach to coding in R is from the \href{https://www.tidyverse.org/}{Tidyverse} collection of packages and developers, who strive to tidy up this wild west environment. Though Tidyverse is powerful, it still has limitations. It is wise to learn the basics of base R's language even if we wish to join the Tidyverse because many packages may be very useful yet not use Tidyverse conventions.

R is not only open source; it is very powerful. Although proprietary statistics programs are easier to use, we limit our capacity when we commit to their workflows. With R, collaboration does not require everyone pay for a license---there is no license. Published articles often include R code in their appendices for readers to use for their own work, which is powerful for continuing our data-analysis learning beyond our university education experience. Also, say you want to use what you learn in graduate school later on in your professional work. If your workplace does not pay for that proprietary license, you're at a loss. This is not a concern with R. Save your R files for adaptation for your future needs.

We can accomplish almost all of the same things in R as we can with proprietary programs. It also allows us to do things that otherwise would require multiple applications. We can manage all of our data and outputs from our analyses in a single project and save these in a reproducible format (i.e., our script). In contrast, with proprietary programs, we might have to juggle files between programs, which invites human error.\footnote{For instance, we might manage data in one program, such as SPSS, save that data into a format for another program, such as MPlus, import that file into MPlus, then export those data back into another program, such as SPSS for prettier graphics. In R, all of our steps are pretty much in the same place.} Once we have a comfortable R workflow, we can continue learning new things in R and contribute our findings to the world.
